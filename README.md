# 医学生学习伙伴与循证答疑 Agent

面向医学生课程学习与科研拓展的桌面智能体。首要目标是陪伴用户完成理解、复习、练习和拓展，而不只是生成一份经过审核的答案。课程材料检索与医学证据核验作为后台护栏；前台将根据连续对话、理解反馈和学习偏好，选择换一种解释、回到课件、寻找视频或进行论文拓展。完整产品原则见 [`LEARNING_COMPANION_ARCHITECTURE.md`](LEARNING_COMPANION_ARCHITECTURE.md)。

## 当前能力

- PySide6 桌面端、多会话本地历史和五种回答模式。
- 多学科课程路由：学科与回答模式相互独立，支持自动识别或手动选择解剖学、组织胚胎学、生理学、生物化学、病理学、病理生理学、药理学、微生物与免疫学、诊断学、内科学和外科学；跨学科题可同时路由多个课程。
- 知识库为教材自动标注学科，并允许用户在知识库界面人工校正；课程检索按学科隔离，避免拿其他学科教材为当前问题背书。
- 连续学习反馈：能够理解“还是不懂、举个例子、找视频、找论文”等追问，并继承上一轮知识点；界面按钮直接传递动作 ID 与当前知识点，不再反向猜测固定文案。“换一种讲法”采用轻量提示词控制，要求模型以亲切的学习伙伴口吻，用白话、短句、分步骤和直观类比重新解释。
- 每个会话独立保存当前知识点：连续的“举例→找视频”不会把动作指令误当主题，明确提出新知识点时则立即切换；否定反馈和出题请求优先于“懂了”等片段词。
- 回答后的可点击学习动作，可直接切换解释方式、回到课件、练习或寻找拓展资源。
- 视频学习分支会先由模型从当前问题与连续对话中提炼1至3组检索关键词，再通过Bilibili结构化搜索取得具体视频，由模型按知识点相关性和教学适配度筛选最多3个候选并说明推荐理由；只有具体视频获取失败时才提供明确标注的关键词搜索入口。
- 豆包视觉识别接口与可配置的大语言模型路由。
- PDF 教材目录识别、教材页码与 PDF 页码映射、逐页文本索引；PPTX 课件按原始幻灯片顺序直接提取文本并建立“幻灯片 N”定位，无需先转成 PDF。
- PPTX 图表页采用二阶段索引：本地导入不会上传课件；用户明确确认后，程序优先渲染完整幻灯片（包括标题、箭头、多图组合和原生图形）再发送给视觉模型，只有渲染不可用时才退回主图。低置信度或存在不确定文字的结果进入可编辑的原图对照复核页；未经人工确认的关键数值、上下标和方向关系不能单独支撑医学结论。批量识别可取消并从剩余页面续跑。
- 本地检索采用“结构召回 + 问题覆盖度重排”：选择题以题干为主检索、选项逐项补查，保留 β/ω 等医学关键符号并统一“脂酸/脂肪酸”等同义写法；过滤装饰图、网页工具栏及只有相同关键词但不能回答当前问题的页面。
- 教材命中页会连同相邻的连续反应页进入证据包，但每页仍保留独立页码、原文跨度和哈希，可分别引用和核验；首轮答案声明缺失子问时，系统还会执行一次有预算的课程内定向补检索。
- 课程资料优先检索和可追溯教材引用。
- 课程资料不足时的三级证据策略：仅课程资料、课程优先外部补证、深度外部检索。
- 外部补证先做问题分类与双语检索式规划；未经内容核验的候选资料不能决定答案。
- 外部来源按 A-E 分级并使用分场景发布门槛：术语、基础医学、临床诊疗和科研拓展采用不同规则。
- 基础医学题在课程资料缺失时不再误走论文检索：可生成明确标注“未与课程资料核对”的通用知识讲解，并经过独立一致性复核；选择题会逐项判断并识别疑似病题。
- 临床诊疗题只有取得可逐字核验的指南、共识或国家公共卫生机构官方处置指引正文，才能进入外部答案核验；摘要和普通论文只能作为候选。
- WHO 官方出版物 API 已自动接入：检索结果再次按指南标题校验，开放 PDF 仅在内存中解析并留下哈希；普通 WHO 报告不会自动升级为指南。
- CDC 公开低血糖处置指引已接入，用于补足教材只讲机制、不讲一般急救步骤的问题；ADA Standards of Care 可定位到官方入口，但因正文自动处理许可限制不抓取全文。
- WHO 指南全文会按问题主题词和 recommendation/should/must 等推荐语义定位，生成最多 6 条精确证据段；每段保留字符区间和全文 SHA-256，整篇 PDF 不写入会话结果。
- 同一运行会话内最多缓存 4 份已解析官方 PDF 文本，采用 LRU 淘汰且不落盘；重复追问无需反复下载，应用退出后缓存自然清除。
- 外部指南答案使用单独生成与核验链：原子主张、直接答案和解释都必须由独立核验模型返回可在证据段中逐字定位的引文；通过后明确标注“官方指南答复｜非课程教材证据”，失败则保持拦截。
- NICE 正式 Syndication API 需要单独许可，国家卫健委官网暂无稳定公开 API 且有反自动化校验；两者已保留连接器接口和官方入口，不使用绕过式爬虫。
- 官方来源的自动化状态、接入要求和人工复核入口已通过应用服务暴露为稳定接口，后续 PySide 页面无需硬编码来源策略。
- PySide 侧栏“官方证据源”入口可查看 WHO、CDC、ADA、NICE 和国家卫健委当前接入状态及官方复核链接。
- Plan-and-Execute 总控与 ReAct 式执行步骤。
- 确定性证据检查、逐条医学主张语义核验和有限定向修订。
- 苏格拉底式、快速答疑、引导学习和科研拓展模式。
- Wikipedia 术语检索，国内环境优先中文条目。
- PubMed 与 OpenAlex 双源论文检索、DOI/标题去重、摘要原文引用和独立复核。
- 对带 PMCID 的指南/共识候选，使用 PMC 官方 OAI-PMH 接口顺序获取许可开放的 JATS 正文；记录正文链接、长度与 SHA-256，不把全文直接写入界面结果。
- 主界面可独立切换“医学视野拓展”：关闭、仅科研模式、每次答题均拓展；课程答案与论文拓展严格分栏。
- 论文拓展只发布绑定摘要逐字引文并通过独立复核的原子化主张，自由概述和未核验候选不会作为结论展示。
- 年份、研究类型筛选和可点击论文证据卡片。
- 真实执行轨迹展示，不显示隐藏推理。
- 回答运行期间可点击“停止回答”；整轮默认上限为3分钟，停止、超时或关闭窗口都会在当前网络步骤结束后的安全检查点退出，不发布未完成答案。
- 人工审核的 Skill 知识沉淀与相似问题召回。
- 医学题库评测、错误归因、Skill 消融开关和无模型检索诊断；选择题额外计算完整选项集合准确率，同底座模型匿名对照记录双方耗时与 Token 用量作为成本依据。

## 核心流程

```text
用户问题/图片
    ↓
视觉观察（可选）
    ↓
问题澄清与模式规划
    ↓
课程资料结构路由 → 页面检索 → 证据包
    ↓
来源、页码、哈希和原文跨度检查
    ↓
基于证据生成答案
    ↓
独立语义核验 → 必要时定向修订 → 发布/拒绝
    ↓
本地证据不足：按证据策略分类 → Wikipedia术语/基础参考
              → 低风险基础题通用知识讲解 → 独立一致性复核 → 透明标注
              → 临床/科研问题才进入 PubMed + OpenAlex
              → 指南/共识 PMCID → PMC 开放全文 → 外部答案核验资格门
              → 未核验候选单独展示，不伪装成课程证据
    ↓
科研模式：双语规划 → PubMed + OpenAlex → 跨库匹配
          → 摘要逐字引用 → 独立复核 → 论文卡片
```

已审核 Skill 只能作为历史提示，不能替代当前问题的教材或论文证据。医学类 Skill 没有证据锚点时禁止启用。

## 运行

推荐使用 Python 3.13：

```powershell
py -3.13 -m pip install -r requirements.txt
py -3.13 main.py
```

也可以双击 `run_app.bat`。

首次运行需要在设置向导中填写模型名称、供应商、API 地址和 API Key。公开配置只保存密钥引用，真实密钥不会写入公开 JSON。

正式使用 OpenAlex 时建议设置：

```powershell
$env:OPENALEX_API_KEY="你的 OpenAlex Key"
```

PubMed 低频查询可以不配置 Key；正式部署可设置 `NCBI_API_KEY` 和 `NCBI_EMAIL`。

## 评测

桌面端点击“题库评测”可以：

- 导入 [`evaluation_question_bank_template.json`](evaluation_question_bank_template.json) 格式的题库；
- 运行完整端到端评测；
- 关闭或启用 Skill 做消融实验；
- 仅运行课程检索诊断，不调用任何模型；
- 自动保存逐题错误归因和汇总指标。
- 生成“完整智能体 vs 直接大模型”的匿名 A/B 学习体验包，供不了解实现的医学生按直接性、易懂程度、病题诊断、引用相关性和学习帮助度评分；答案来源密钥单独保存，避免评分偏见。
- 对官方指南回退题额外检查答案来源和发布门槛，区分“官方证据正确发布”“摘要候选安全拦截”和“运行失败”。

[`official_guideline_evaluation_template.json`](official_guideline_evaluation_template.json) 是官方指南专项评测模板。它不包含正式答案，必须由教师或临床专家补充指南版本、适用人群和必要概念后才能作为评测数据。

当前仓库包含 [`development_retrieval_bank.json`](development_retrieval_bank.json)，它仅用于开发诊断，不能作为正式比赛成绩。当前 6 题开发集的 Top-3 检索命中率为 100%，结果见 `data/evaluations/development_retrieval_diagnostic.json`。

`data/evaluation_imports/physiology_candidate_bank_from_题目_1.json` 是从用户提供的《题目(1)》人工转录并经用户确认为开发用途的 10 题评测集。当前无 Skill 严格开发评测通过 9/10（90%），教材来源级检索命中 10/10，已发布答案的双重引用核验通过率为 100%；唯一失败项是现有课程语料缺少休克用药原则，系统按证据不足安全拦截。详见 `data/evaluations/题目_1_development_summary.md`。以上均为开发调优结果，不是正式盲测成绩。

`data/evaluation_imports/clinical_physio_development_from_临床问题_1.json` 是17道临床生理学问题开发集。2026-10-07 关闭 Skill 的完整重跑中，14题正常发布、3题进入人工复核，预期流程结果一致率为82.4%；教材来源级检索命中率和已发布答案引用核验率均为100%。固定术语评分仍存在同义表述假阴性，且两道临床用药题只完成教材机制部分而未升级为官方外部答案，因此该结果只用于开发诊断。详见 `data/evaluations/临床问题_1_core_full_after_recharge_2026-10-07.json`。

正式报告必须使用独立、由教师或命题者确认且未参与调参的题库。

## 数据与安全

- 会话历史保存在本机；题目原图放在 `data/conversation_images/<会话ID>/`，识别题干保存在会话记录中。删除对话时会删除该会话保存的图片，不保存 API Key 或模型隐藏推理。
- 重新发送已保存的原图给视觉模型前，仍需本轮单独批准。
- 外部网页和论文不能覆盖系统指令，只作为检索数据。
- 外部检索失败不会破坏已核验的课程答案。
- 未通过全部验证门的医学答案不会展示。
- 运行错误不计作幻觉拦截成功。
- 开发集、正式测试集和人工诊断结果必须分开报告。
